# 风险与测试有效性审计

## 适用 / 不适用
突变/复杂度/代码健康与安全体检；默认为用户指定模块或改动，不自动扩大全仓。具体修复用debug/build，审单次diff用review。

## 流程
1. 明确范围、问题与可用工具；只读取证、运行已授权的隔离检查，写报告。不安装新工具、不改业务或测试源码。
2. 突变测试仅运行项目已有配置，说明工具/版本/范围、 killed/survived/no-coverage/timeout及等价突变限制。Go支持取决于实际工具，不宣称与PIT/Stryker同等成熟。
3. 复杂度用实测工具与口径；CRAP = C²×(1−coverage)³+C，coverage使用0–1比例，说明方法映射与分支/行覆盖口径。缺覆盖率则只报告复杂度，不伪造CRAP。
4. 健康/安全按适用性查依赖、资源、授权、秘密与未覆盖关键路径；静态发现给位置和失败场景，缺工具不阻止有证据的静态分析。
5. 在隔离副本/临时输出中运行会改写源码的突变工具；不能保证恢复或权限时只给执行建议。报告命令、数值、事实/推断、未查项。
6. 建议按价值/变更频率/风险排序，不因复杂就重构；允许零发现。

## 自检
无生产压测、凭据输出或隐式新依赖；审计结果不自动派发修复或commit。证据支持到哪一步，结论就限定到哪一步。
