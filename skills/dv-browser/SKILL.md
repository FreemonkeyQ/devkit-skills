# 浏览器验收

**不用测试通过代替亲眼看过。** 这个技能的产物是「我实际在浏览器里做了什么、看到了什么」，不是「测试全绿」。

## 适用 / 不适用

适用：界面类改动的验收；交付前点一遍；极端数据与边界；性能与内存问题。

不适用：纯后端改动 → `/dv-test run`；要写 E2E 测试用例 → `/dv-test design`；要审代码 → `/dv-review`。

## 流程

1. **起服务**。用 `config.commands.dev` 与 `config.frontend.devUrl`。起不来就别往下走，报告原因。
2. **侦察再行动**。先取快照/DOM 结构确认元素与文字，再操作；不要盲点坐标。
3. **按验收标准逐项操作**，每项记录：操作、观察、结论。
4. **视觉检查（有界面时）**：
   - 文字是否重叠、是否溢出容器
   - 控件与文字是否对齐
   - 长文本、空列表、超多条目下的布局
5. **极端数据**（逐项，至少 6 条）：超长名称 / 空列表 / 1 万条 / 超长邮箱 / 超大数字 / 缺图。
6. **性能与内存**（按需）：关键路径的加载时间、长列表滚动是否掉帧、反复进出页面是否内存持续上涨。
7. **落盘结论**。

## 输出格式（固定）

```
## 环境
URL / 命令 / 视口尺寸

## 逐项验收
| # | 操作 | 预期 | 实际 | 结论 |

## 视觉检查
- 重叠：<有/无 + 位置>
- 对齐：<有/无 + 位置>
- 极端数据：<每项一行>

## 性能
<关键数字或「本次未测」>

## 我实际看到 vs 我推断的
- 直接观察到的：…
- 通过 DOM/几何/截图数值推断的：…
- 未核对的：…
```

## 硬约束

- 最后一段必须写。**读不到图时必须声明「未做像素级肉眼核对，结论基于 DOM/几何/探针」**，不允许暗示「我看到了」。
- 不因自动化测试全绿就跳过浏览器验收。
- 发现的问题只报告；要修 → `/dv-build`。

## 自检

- [ ] 服务真的起来了，URL 与命令已记录
- [ ] 每个验收项都有实际操作记录
- [ ] 视觉检查有具体位置，不是「看起来正常」
- [ ] 极端数据 6 项逐条
- [ ] 最后一段区分了观察 / 推断 / 未核对

## 反合理化

| 我本来想说 | 现实 |
|---|---|
| 「单元测试都过了，应该没问题」 | 测试不覆盖真实渲染与布局 |
| 「页面看起来没问题」 | 要有位置和数值，否则无法复现 |
| 「截图我看了」 | 若读不到图，必须说明结论来自探针 |
| 「极端数据不太可能发生」 | 用户输入永远会超出预期 |
