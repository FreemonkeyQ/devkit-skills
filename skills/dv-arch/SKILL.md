# 架构与迁移方案

## 适用 / 不适用
模块边界、测试接缝、依赖/数据/API迁移、复杂结构改进。具体Bug交debug，直接实现交build。此技能只设计，不改业务代码。

## 流程
1. `shape` 分析现有职责、依赖、运行与数据约束，提出结构；`migrate` 设计兼容迁移与回滚，两模式均只写方案。
2. 沿用项目风格和版本，不自动套DDD/微服务。考虑API、事务、并发、持久化、权限、可观测性和桌面进程边界。
3. 以接口清晰、隐藏复杂性、测试边界为评价，不以类数量或接缝最少为硬指标；选择能覆盖真实风险的验证层。
4. 有真实取舍时比较方案；确定的小改可只给一种。识别影响范围、风险、迁移成本。
5. 宽迁移考虑expand→migrate→contract，约定每批兼容验证、退出标准和回滚；无法逐批绿时说明整合批次，不假装可独立交付。
6. 复用已有ADR/方案目录，仅用户要求或项目约定时记录。批准实施后交plan/build，不在方案技能偷偷执行迁移。

## 自检
源代码与事实支撑方案；重要不可逆决策需要确认；允许零改进候选，结构复杂不等于必须拆分。
