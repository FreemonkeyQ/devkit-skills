# 存量页面整合与改版

用于 `redesign` 模式。目标是把现有页面收敛成一套可维护、可迁移的界面，而不是整体推倒重写。

## 1. 盘点
先建立页面清单，每行至少包含：
- 页面/路由、入口位置、主要用户任务。
- 权限与角色、关键状态（空/加载/失败/无权限）、深浅链接。
- 复用的组件、设计令牌、埋点事件、被外部引用的链接或SDK。
- 现状问题：重复页面、导航分叉、状态缺失、视觉漂移、性能或无障碍缺陷。

盘点以代码和运行界面为准；文档与截图只能辅助，冲突时记录差异。

## 2. 处置决策
对每个页面给出一种处置：
- 保留：继续使用，只做视觉与状态补齐。
- 合并：多个页面收敛到一个，明确承接的任务与跳转。
- 下线：无入口或无用户任务，确认权限、埋点和外链影响后处理。
- 新增：现有结构无法承接的任务，说明为何不能复用。

产出“页面→任务→处置→依赖”表，先和需求方确认再改。

## 3. 目标信息架构
- 定导航层级、命名和URL策略；一级导航按用户任务划分，不按历史模块划分。
- 统一术语，去掉同义入口。
- 明确哪些旧入口保留兼容、哪些重定向、哪些彻底移除。

## 4. 分批迁移
默认顺序，每批可独立上线：
1. tokens 与基础组件统一，先消除视觉漂移。
2. 应用壳、导航与权限框架，保证新旧页面能共存。
3. 高价值或高流量页面，按 design 模式逐页改造。
4. 长尾页面合并/下线，清理遗留路由与样式。

避免大爆炸式重写；无法分批时说明原因、整合批次和回滚方式。

## 5. 兼容与边界
- 旧路由重定向、权限映射、埋点事件名、外链与客户端深链都要有清单。
- 路由、模块、数据或API层面的迁移方案交 dv-arch；本技能只定界面与IA决策。
- 新旧页面共存期要有明确的视觉过渡策略，避免两套导航长期并存。

## 6. 每页改造
- 先保证行为与权限一致，再改视觉与布局。
- 按 design 流程补齐状态矩阵；不为静态页造无关状态。
- 复用已确认的 tokens 和组件，不逐页引入新样式。

## 7. 证据与验收
交付时包含：
- 页面覆盖表：已迁移/进行中/未迁移，及对应路由。
- before/after 截图，至少覆盖关键页面和窄宽度。
- 状态覆盖与权限回归结果；关键路径交 dv-browser。
- 遗留项与风险：未下线旧入口、临时兼容代码、待补埋点。
