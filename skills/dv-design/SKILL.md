# 可落地的产品界面与交互设计

## 适用 / 不适用
新界面、改版、整站视觉重构、存量页面整合、异常态、动效、视觉一致性与交接。需求不明确交grill；生产实现交build；路由/模块/数据/API迁移交arch；验收交browser。本技能只写设计决策与隔离原型，不改业务代码。

## 模式
- `design`（默认）：单页或单条流程，定结构、状态、交互与动效。
- `aesthetic`：高设计感打磨，先定视觉方向与反套路底线，再落到页面。
- `redesign`：存量系统整体改版与页面整合，走盘点→目标IA→分批迁移→逐页改造→对比验收。
可组合：redesign 的每页仍按 design 做；视觉上限按 aesthetic 把关。

## design 流程
1. 复用现有品牌、设计系统和组件库，先看当前界面/需求，明确Web或桌面端。无视觉资料时说明限制，不固定为同一种AI模板。
2. 定信息层级、用户任务、主次操作和导航；重大方向可给2版比较，小改不用多版原型。
3. 检查适用状态：默认/加载/空/失败/权限/超限/离线；不适用项写原因，不为静态页面造无关状态。
4. 明确布局、排版、配色、间距、焦点与响应式；复用已有tokens，必要时补而不是重建整套系统。需要视觉方向时读 `references/visual-direction.md`。
5. 动效解释目的、工具/属性、时长/easing、打断与退出、reduced-motion；没价值就不动。桌面考虑键盘、窗口缩放、高DPI与系统习惯。
6. 按页面数据结构选长文本/空值/缺图/大列表等挑战；不能无条件生成10000条或污染真实数据。
7. 按授权与项目约定输出决策/原型，HTML只是一种选择。可写隔离原型，不改业务代码；重要决定确认后交build。

## aesthetic 模式
1. 先用一句话定方向：目的、受众、调性、让人记住的一点；先定概念，再定样式。
2. 按 `references/visual-direction.md` 避开默认AI套路；字体、配色、构图、质感都要有理由，同一产品全局一套方向。
3. 给1-2个可操作方向并说明取舍，不输出无差别模板；高设计感不牺牲可用性、性能与无障碍。
4. 用 `references/design-review.md` 打分自检，截图证据交browser。

## redesign 模式
1. 按 `references/redesign.md` 盘点现有页面、路由、入口、权限、状态、共享组件与埋点。
2. 产出保留/合并/下线清单和目标IA，先统一导航与共享组件，再改页面。
3. 分批迁移：tokens/基础组件→应用壳→高价值页面→长尾；每批可独立上线，旧路由兼容与重定向方案交arch。
4. 每页按 design 模式补状态；先保行为一致再改视觉，避免整体重写。
5. 记录 before/after 截图、未迁移清单与回归结果；关键路径交browser验收。

## 交接
交付物包含设计理由、状态清单、tokens、工程约束、未决项与影响范围，不只“好看”的泛泛建议。HTML原型隔离存放，不冒充生产实现；无法实测的视觉与辅助技术效果明确标注。

## 自检
明确实际观察与推断；对比度、键盘和状态不是事后补丁。改版不破坏既有权限、路由与埋点；零视觉改动也是合法结论。
