# 可落地的产品界面与交互设计

## 适用 / 不适用
新界面、改版、异常态、动效、视觉一致性与交接。需求不明确交grill；实现生产代码交build；验收交browser。

## 流程
1. 复用现有品牌、设计系统和组件库，先看当前界面/需求，明确Web或桌面端。无视觉资料时说明限制，不固定为同一种AI模板。
2. 定信息层级、用户任务、主次操作和导航；重大方向可给2版比较，小改不用多版原型。
3. 检查适用状态：默认/加载/空/失败/权限/超限/离线；不适用项写原因，不为静态页面造无关状态。
4. 明确布局、排版、配色、间距、焦点与响应式，参考 references/design-engineering.md。复用已有tokens，必要时补而不是重建整套系统。
5. 动效解释目的、工具/属性、时长/easing、打断与退出、reduced-motion；没价值就不动。桌面考虑键盘、窗口缩放、高DPI与系统习惯。
6. 按页面数据结构选长文本/空值/缺图/大列表等挑战；不能无条件生成10000条或污染真实数据。
7. 按授权与项目约定输出决策/原型，HTML只是一种选择。可写隔离原型，不改业务代码；重要决定确认后交build。

## 自检
明确实际观察与推断；对比度、键盘和状态不是事后补丁。交付物包含设计原因与工程约束，不只有“好看”的泛泛建议。
