# 设计

不做完整 PRD，不做用户研究、竞品拆解、情绪板、海报。只产出**工程能直接实现**的设计决策。

## 适用 / 不适用

适用：新页面/新交互要定结构；状态与异常态没穷举；动效要不要做、怎么做；要给工程交接设计。

不适用：需求还没定 → `/dv-grill`；要写完整 PRD → `/dv-plan spec`；要验收实现 → `/dv-browser`。

## 流程

1. **判定入口**：新建设计 / 已有 PRD 转设计 / 改版。三种走法不同，先确认。
2. **结构**：页面区块、信息层级、主操作、次操作。给一版 HTML 稿（可截图对比）。
3. **状态矩阵**（必须齐）：默认 / 加载 / 空 / 部分失败 / 全失败 / 无权限 / 超限 / 离线。
4. **异常态穷举 6 类**：输入异常、网络异常、数据异常、权限异常、状态冲突、超时。
5. **动效四问**（每个动效逐条答，答不上就不做）：
   - 该不该动？
   - 为什么动（目的）？
   - 用什么曲线与时长？
   - 如何被打断、如何退出？
6. **设计令牌门槛**：对比度（正文 ≥4.5:1）、间距阶、字号阶、圆角与阴影一致。给一张令牌表。
7. **极端数据自检**：超长名称、空列表、1 万条、超长邮箱、超大数字、缺图。逐项写预期表现。
8. **落盘** `docs/design/<slug>/`：`decisions.md` + `mock.html` + `tokens.md`。

## 硬约束

- 不写后端代码，不改业务逻辑
- 动效四问答不全的，明确写「本版不做动效」
- 视觉结论若无截图对照，必须声明「基于结构描述，未做像素级核对」

## 自检

- [ ] 状态矩阵 8 项齐全
- [ ] 异常态 6 类逐条有处理方式
- [ ] 每个动效四问都有答案
- [ ] 令牌表可直接映射到 CSS 变量
- [ ] 极端数据 6 项有预期表现

## 反合理化

| 我本来想说 | 现实 |
|---|---|
| 「主流产品都这么做」 | 那是竞品拆解，本技能不做 |
| 「异常态回头补」 | 异常态是设计的一部分，不是补丁 |
| 「动效加上去更高级」 | 四问答不上就是不加 |
| 「这个页面简单，不用状态矩阵」 | 越简单的页面越容易漏空态 |
