# 路由

只给**一个**下一步，不解释技能细节——要看手册用 `/dv-help`。

## 适用 / 不适用

适用：不知道下一步；不确定该用哪个技能；想让人按状态机推进。

不适用：想了解技能本身怎么用 → `/dv-help`；已明确知道要做什么 → 直接执行。

## 流程

1. 读 `.devkit/state.json`。没有就按「新任务」处理，并建议先跑 `/dv-context`（仅当仓库无 `AGENTS.md` 技能段时）。
2. 按处境匹配下表，取**第一命中**，只输出一个。
3. 输出格式固定三行：

```
下一步：/dv-<name>
理由：<一句话，引用用户原话里的关键词>
如果你其实想<另一种可能>，改用 /dv-<other>
```

## 路由表

| 处境 | 推荐 |
|---|---|
| 需求模糊 / 方案没底 / 要跟人对齐 | `/dv-grill` |
| 已谈定，要变成 spec 和工单 | `/dv-plan` |
| 有工单，要写代码 | `/dv-build` |
| 报错 / 失败测试 / 变慢 / 偶发 | `/dv-debug` |
| 要查资料 / 比方案 / 核实版本差异 | `/dv-research` |
| 有 diff 要审 / 提交前 / 开 MR 前 | `/dv-review` |
| 写完了要交 | `/dv-done` |
| 页面 / 交互 / 动效 / 异常态 | `/dv-design` |
| 模块边界 / 要动结构 | `/dv-arch shape` |
| 大范围机械改动 / 换 API / 迁移 | `/dv-arch migrate` |
| 要设计测试用例 | `/dv-test design` |
| 要写或跑测试 | `/dv-test run` |
| 测试是否有效 / 复杂度体检 | `/dv-audit` |
| 浏览器验收 / 极端数据 | `/dv-browser` |
| 新仓接入 / 状态与配置不一致 | `/dv-context` |
| 改 devkit 自己 | `/dv-author` |
| 就是不知道 | `/dv-help` |

判定优先级：**症状优先于阶段**。报错时即使 stage 是 build，也走 `dv-debug`。

## `--auto` 托管

进入后按 `state.json` 的 `next` 推进，**只在三处停**：

1. spec 定稿前
2. 工单拆分后、开工前
3. 提交前

停止时输出：

```
⏸ 待确认：<要确认什么>
确认后继续：回复「继续」，或直接改，或说「停」
```

不在确认点之间询问「要不要继续」。用户说「停」立即退出托管并输出当前 stage。

## 停止条件 / 自检

- 只输出一个推荐，不列备选清单
- 不解释技能内容，不贴技能正文
- 不修改任何文件（包括 state.json）
- 用户已明确说要做什么时，不再路由，直接确认一句「好，走 /dv-x」并结束

## 反合理化

| 我本来想说 | 现实 |
|---|---|
| 「这里有 3 个方案你可以选」 | 路由的职责是减少决策，不是增加 |
| 「先解释一下这个技能怎么工作」 | 那是 `/dv-help` 的活 |
| 「顺便帮你把状态文件更新一下」 | 路由只读 |
