# 按任务选方法

## 适用 / 不适用
不知道下一步、需求模糊、要求按目标推进时使用。查询用法优先 dv-help；单次事实查询直接回答。

## 流程
1. 阅读用户当前目标与仓库规则；状态文件仅作恢复提示，不能覆盖新指令。
2. 判断意图：只讨论、设计、实施、评审、提交、推送。默认最短路径，不要求所有任务建工单。
3. 选择一个主技能；确有需要时关联测试/设计等技能。实际调用宿主提供的技能入口；不能调用则说明降级方式，不声称已执行。
4. 无授权执行时仅给推荐与理由；明确委托实现时继续推进，不把每次加载技能都作为审批。
5. `--auto` 等同于本次目标内的目标模式，不是无限循环或权限提升。重要未定决策、范围变化、提交/推送/生产审批必须遵守授权边界；终点未包含 Git 动作时不 commit/push。阻塞时报告已完成部分与缺口。

## 链路模式
1. 逐步模式（默认）：每个技能按 `references/chain.md` 输出三行交接；用户确认下一步后立即调用，不重复完整侦察。
2. 目标模式：用户说“根据 dv Skill(s)/技能执行”“按链路走完”“一直做到 done/push”时，先给起点→终点、技能序列、停车闸门和授权范围；确认后连续执行。
3. 停车闸门：范围变化、未定决策、不可逆或共享副作用、Git 动作超出终点、失败或阻塞时停。终点写 push 才 commit/push，不隐含 force/merge/PR/部署。
4. 两种模式都不放宽技能原有授权；`next` 只是候选图。

## 路由
模糊需求→dv-grill；已确认方案→dv-plan；明确实现→dv-build；报错→dv-debug；技术调查→dv-research；页面/动效→dv-design；结构/迁移方案→dv-arch；用例/执行测试→dv-test；测试有效性/体检→dv-audit；真实UI验收→dv-browser；审改动→dv-review；完成验证汇报→dv-done；规范提交→dv-commit；推送/commit push→dv-push；仓库接入→dv-context；维护技能→dv-author；用法→dv-help。

## 技能交接
收尾给三行：已完成；建议下一步（有 metadata.next 时选 1 个默认，可附 1 个备选）；需用户决定的事。用户确认即直接调用下一步，不重复完整侦察；目标式委托与停车闸门见上方链路模式。

## 输出与自检
说明本次路径及范围，只有真实调用才说已调用。用户确认下一步后立即调用，不把同一决定重复成新的审批。禁止把“做完了吗”解释成提交授权；禁止将普通报错解释成生产写入授权。确认问题仅限影响下一步的真实决定。
