# 按任务选方法

## 适用 / 不适用
不知道下一步、需求模糊、要求按目标推进时使用。查询用法优先 dv-help；单次事实查询直接回答。

## 流程
1. 阅读用户当前目标与仓库规则；状态文件仅作恢复提示，不能覆盖新指令。
2. 判断意图：只讨论、设计、实施、评审、提交、推送。默认最短路径，不要求所有任务建工单。
3. 选择一个主技能；确有需要时关联测试/设计等技能。实际调用宿主提供的技能入口；不能调用则说明降级方式，不声称已执行。
4. 无授权执行时仅给推荐与理由；明确委托实现时继续推进，不把每次加载技能都作为审批。
5. `--auto` 是本次目标内的协作请求，不是无限循环或权限提升。重要未定决策、范围变化、提交/推送/生产审批必须遵守授权边界。阻塞时报告已完成部分与缺口。

## 路由
模糊需求→dv-grill；已确认方案→dv-plan；明确实现→dv-build；报错→dv-debug；技术调查→dv-research；页面/动效→dv-design；结构/迁移方案→dv-arch；用例/执行测试→dv-test；测试有效性/体检→dv-audit；真实UI验收→dv-browser；审改动→dv-review；完成验证汇报→dv-done；规范提交→dv-commit；推送/commit push→dv-push；仓库接入→dv-context；维护技能→dv-author；用法→dv-help。

## 输出与自检
说明本次路径及范围，只有真实调用才说已调用。禁止把“做完了吗”解释成提交授权；禁止将普通报错解释成生产写入授权。确认问题仅限影响下一步的真实决定。
