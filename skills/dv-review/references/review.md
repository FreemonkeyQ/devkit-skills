# 改动评审

- 范围类型：工作区 / 分支 / 指定提交
- 基线与 HEAD：
- 命令：按范围选择 diff、cached diff、git show 等
- 相关未跟踪文件 / 排除文件：
- 需求依据：当前要求 / 工单 / 规格 / 变更提案 / 缺失
- 日期：YYYY-MM-DD

## Correctness

真实 Bug 场景、代码位置、证据、反例复核；无发现合法。
触及数据库、循环内 I/O、无界集合、分页或热路径时，检查性能证据：N+1、无界结果、深分页、索引/EXPLAIN；没有实测就标未验证，不把建议当已实现。

## Standards

文档化规范来源；代码味道/审美为判断建议而非 Bug。
检查复用与约定：是否先找现有实现、依赖和同模块模式；新增依赖是否有理由；是否把少数派写法当成项目约定（证据不足 3 处）。

## Spec

缺失、超范围、错误实现；无依据记 unknown/未评估而不是通过。

## 摘要与局限

各轴发现、关键风险、未查范围、需要的下一步；不自动修改或提交。
