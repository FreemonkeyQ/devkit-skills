# 正确性判断与误报复核

## 何时读取

遇到潜在 Bug、输入可达性不清、规范与正确性混淆，或需要复核评审意见时读取。普通小改动不必展开全部案例。本文是方法，不提供修改源码或执行有副作用操作的授权。

## 从怀疑到发现

1. **固定契约**：找当前需求、接口约定或真实调用方，说明期望行为。没有依据时记录未知，不把个人偏好当契约。
2. **构造失败场景**：写出输入、角色、状态与必要时序，以及实际错误结果。只说“可能出问题”不足以确认。
3. **检查可达性**：沿入口和调用链检查校验、类型、默认值、异常处理与生命周期。类型声明不一定约束外部运行时输入；上游校验也不一定覆盖所有调用方。
4. **寻找反证**：主动找能使判断不成立的保护、业务例外或测试；区分“这个分支不可能到达”和“目前没看到调用”。
5. **选择最低成本验证**：优先现有测试或只读代码证据，必要时在授权的隔离环境复现。记录实际运行的命令；没运行不写“已复现”。
6. **形成结论**：位置、契约、失败场景、证据与剩余不确定性连成一条链。代码快照变化后重新核对。

| 结论 | 所需依据 | 表述 |
|---|---|---|
| 确认的正确性缺陷 | 可达输入/状态与错误结果有充分代码证据或复现 | 标明静态确认或实际复现，不混淆两者 |
| 待验证风险 | 失败假设合理，但调用条件、时序或契约缺关键证据 | 指明缺什么、如何验证，不计为已确认 Bug |
| 建议 | 有替代写法或维护收益，但未证明错误行为 | 放建议或 Standards，说明权衡 |
| 无发现 / 未评估 | 检查后未证实问题 / 缺少检查依据 | 两者分开；不以未评估冒充通过 |

严重度看真实影响、受影响范围与可触发条件；置信度看证据完整性。不能因为影响严重就把置信度提高。报告按既有三轴分段，不要求机器格式。

## 案例一：可达的跨租户读取

契约：用户只能查看自己租户的订单；不存在或不属于自己均返回 not-found。调用方已认证，但没有检查订单租户。

```python
def visible_order(orders, order_id, tenant_id):
    return orders.get(order_id)
```

证据：`orders` 含 `{"o2": {"tenant_id": "t2"}}`，租户 `t1` 的用户可向此入口传 `o2`。参数 `tenant_id` 未参与判断，返回另一租户订单。

反证检查：确认是否存在公共订单例外、存储是否已按租户隔离、此入口是否还有统一授权层。案例已明确这些保护不存在，因此可静态确认越权；若实际项目尚未核查，结论应为待验证。

报告示例：Correctness — 已静态确认；该入口对 t1 查询 o2 返回 t2 订单，违反租户隔离；未执行运行时复现。修复请求另走 build/debug，不在只审查任务中改源码。

## 案例二：看似缺校验，实际入口有完整保护

```python
def _ratio(percent):
    return percent / 100


def parse_ratio(percent):
    if not isinstance(percent, int) or isinstance(percent, bool):
        raise ValueError("integer required")
    if not 0 <= percent <= 100:
        raise ValueError("out of range")
    return _ratio(percent)
```

契约：公开入口接受 0–100 的整数，非法输入抛 ValueError；已检查全部调用，`_ratio` 仅由 `parse_ratio` 调用。

初始怀疑：“_ratio 没有范围校验，150 会产生非法结果。”反证：公开入口在调用前拒绝 150；在给定调用范围内失败输入不可达。不应报告已确认 Bug。可建议补边界回归测试；若未来发现其它调用方，再基于新证据判断。

## 停止条件

证据足够则报告；关键事实不可获取则列待验证项及最小下一步。不为凑发现扩大到全库，不无限枚举假设。不要把“未找到反证”当成“已经证明可达”。
