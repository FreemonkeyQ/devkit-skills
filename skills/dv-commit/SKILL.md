# 规范本地提交

## 适用 / 不适用与授权
“提交一下”“规范提交”“按功能分批commit”授权本次范围内本地提交，不授权push。
“整理提交信息，不提交”“看看怎么分批”仅检查/草拟。明确授权后不重复机械确认；范围混杂、敏感文件或重要分批取舍才问。

## 流程
1. 读取仓库提交规范、当前分支与操作状态、`git status --porcelain=v1 -z`、暂存/未暂存diff、未跟踪文件和近期提交风格。冲突/merge/rebase/cherry-pick未完成时停止并说明。
2. 固定范围：任务相关改动默认可提交；“全部”涵盖全部可提交内容，仍排除凭据/运行数据/非预期生成产物。既有暂存是线索，不是覆盖授权；无关和来源不明内容保留。
3. 按一个连贯意图组织一批：同功能代码+测试+必要文档同批，独立功能分批；独立重构/格式化可分；宽迁移按兼容阶段。不按前后端或文件数拆出不能运行的中间状态。同文件不同任务仅在能安全分块时分批，不能分则说明，不改源码以美化历史。
4. 生成基于实际diff的信息：仓库规则优先，无规则用`type(scope): summary`，中文摘要可用；正文解释原因/关键变化，确有验证则附记录。遵守宿主要求的签名/署名。
5. 复用有效验证，分批失效时按风险复验。显示简短分批计划；已有授权且范围明确直接执行。精准stage文件/补丁，不默认`git add -A`或reset暂存区；包含暂存外来hunk时先保留/询问，不静默带入。
6. 提交前查看staged diff和秘密风险；不靠`--no-verify`绕过失败hook。失败保留内容与stage状态，报告原因不擅自改依赖/规范。无改动不创建空提交，不默认amend/rebase/squash历史。
7. 记录每个SHA、标题、验证、未提交范围；状态可标committed，不能标pushed。只本地commit，不push/merge/deploy/worktree清理。

## 自检
每批可理解可回滚；已暂存无关内容未混入；消息不夸大修复或测试；用户只要草稿时绝不stage/commit。操作可能更新Git索引，不能声称完全不动stage；说明实际结果。
