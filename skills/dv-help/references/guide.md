# 用法与排错

## 不背技能名
“我想加导出，字段没定”→grill/plan；“按刚才方案实施”→build/test/review/done。
“只分析这个报错别改”→debug诊断；“看看未提交代码有没有问题”→review。
“设计页面”→design，生产实现需实施意图；“跑测试”→test run，不修业务代码。
“把相关修改按功能提交，不push”→commit；“push一下”→相关未commit先commit再push。
“只推已有提交”→push跳过commit；“等部署结果”→CI关联等待，不点击manual审批。
“验证上线后功能”→done release，不从本地部署。
“升级本机 Claude 和 Qoder 的 devkit”→upgrade；先看版本用检查模式。

## 关键区别
- done是验证汇报，commit本地历史，push远程同步，CI部署是第四件事。
- 自动加载方法不等于执行所有副作用。明示只生成提交信息，commit也只能输出信息。
- review工作区包含暂存/未暂存/相关新文件，不只比较HEAD。
- test design不写测试；run可以补必要场景，但不重新做完整需求规划。
- arch migrate只设计分批，不自己执行；build按批准方案执行。
- upgrade只升级本机安装，不等于发布或commit/push；同版本内容刷新前有备份。

## --auto
route --auto是本次目标协作，采用最短路径；不会无限循环，也不固定每阶段确认。
新增重要取舍/范围改变/生产操作遵守授权，用户“停”立即停止。done不能让自动模式偷偷commit。

## 排错
1. 先看宿主是否实际列出技能，插件命名空间和裸路径不同；不要同时装插件和link。
2. 读取description/正文与实际调用日志，不凭模型回答“知道这个技能”证明加载。
3. 旧插件也能命中同类任务，测试时隔离加载范围，不自动卸用户现有插件。
4. config路径相对目标项目根，参考文档相对技能目录；状态不是路由权威。
5. hook可选，无状态/idle/配置损坏时静默；检查开发Python依赖，不能把无提示当成功接入。
6. Qoder的openai.yaml策略消费未知；Codex配置不提供Qoder保险。未实测宿主不承诺支持。
7. 视觉不具备读图能力时报告探针结果和限制；不能因为DOM通过说肉眼看过。

## 维护
不为凑数量而拆更多入口；语言/平台深度放reference。低频部署/迁移/审计不是30天零次就淘汰。
帮助列表由生成表维护，技能语义与行为通过真实场景评估，静态lint只是一层。
