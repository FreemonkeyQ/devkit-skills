# 用 / 不用速查

## 一句话判据
做完之后能否在 30 秒内自己确认对错。能，就不上技能链；不能，或错了代价大、要向别人交代，才值得用。

## 值得用
| 场景 | 路径 | 关键理由 |
|---|---|---|
| 改动会进主干/生产、跨模块联调 | build → test → review → done | 四轴评审与门禁 fail-closed |
| 真实仓库，有禁改或隔离约束 | build + review + done | 范围契约与 changed-files 边界 |
| 需求还模糊，要跟人对齐 | grill → plan | 逐轮收敛未定项，落成垂直切片 |
| 线上报错、偶发、变慢 | debug | 先定位根因并补回归，不急着改 |
| 选型、版本差异、跨模块行为 | research | 一手来源与可追溯结论 |
| 架构边界、兼容迁移 | arch | 只出方案，不动业务代码 |
| 页面结构、动效、空态/异常态 | design | 结构、状态、令牌一起定 |
| 测试是否有效、全库体检 | audit | 突变测试看有效性，不迷信覆盖率 |
| 真实浏览器验收、极端数据 | browser | 真实交互与可引用探针结论 |
| 不知道下一步、要连续执行 | route（`/dv`） | 编排最短路径，不提升授权 |
| 提交、推送、本机升级 | commit / push / upgrade | 显式 Git 与安装边界 |

## 没必要用
- 单点事实查询：某函数在哪、报错什么意思、某张表有什么字段。
- 一行改动：文案、间距、图标、补日志，自己能立刻验收。
- 纯讨论与方案发散：还没到执行，先给推荐和取舍。
- 只读代码理解现状：直接读比走流程快。
- 一次性探索：跑完就扔、不交接不复现。
- 方向未定就拆计划：把没想清的问题固化成假计划。

## 按代价与不确定性组合
| 失败代价 | 不确定性 | 建议 |
|---|---|---|
| 低 | 低 | 不用技能，直接做 |
| 高 | 低 | review + done；行为改动加 test |
| 低 | 高 | grill / research / plan |
| 高 | 高 | 全链，并在 `.devkit/runs` 留证据 |

## 成本与触发（实测）
- 技能增加流程成本，不保证提高正确率。40 格矩阵里，小任务 no-skill 约 146s/18k tokens；链式常见 200–500s、1–5 万 tokens，未观察到稳定增益，失败主要来自超时或运行产物污染。
- 自然触发基本为 0。需要约束时显式点名 `dv-xxx` 或用 `/dv <目标>`，不要把“没自动调用”当成技能不存在。
- 领域知识缺口不会被技能补上。跨仓库评测中，所有臂都漏了项目手册里的过滤规则；这类要先补 `AGENTS.md` 或 `.devkit/project.json` 上下文。

## 默认姿势
- 小改：直接改 → commit（要推再加 push）。
- 中等功能：`/dv 做完 X`，走 build/test/review/done。
- 高风险、跨仓库、要交接：`/dv` 目标模式，验收矩阵与门禁证据落在 `.devkit/runs/<id>/`。
- 只想知道：不开技能，直接问。
