# 诊断实验与结论边界

## 何时读取

根因未明、存在竞争假设、偶发/并发症状或无法复现时读取。已定位的简单错误不必展开完整方法。工具命令按项目现有入口选择；本文不授权生产埋点、外部写入或修复。

## 用实验推进，不靠叙事推进

| 环节 | 要回答的问题 |
|---|---|
| 观察 | 哪个版本、输入、环境出现什么症状？原始日志在哪里？ |
| 假设 | 哪个机制能解释观察？有哪些其它解释？ |
| 预测 | 如果假设成立，改变哪个条件会出现什么可观察差异？ |
| 实验 | 如何隔离变量，以最小安全反馈环区分这些解释？ |
| 结果 | 实际发生了什么？命令、退出码、观测值与预期是否一致？ |
| 更新 | 假设被支持、被否定，还是仍无法区分？下一步信息价值是什么？ |

一次主要改变一个变量；不可避免的环境差异要记下来。排查不能仅靠反复阅读同一段代码后增加信心。修复后恢复原触发条件，避免把禁用了功能、吞异常或降低压力当作修复。

## 贯穿案例：指定状态筛选未生效

业务契约：未传状态不过滤；传状态必须精确过滤，包括数值 0。

```python
def select_rows(rows, status=None):
    if status:
        return [row for row in rows if row["status"] == status]
    return list(rows)
```

观察：导出 status=0 时带上其它状态记录。先核对用户描述、请求参数与实际输出；此案例不解释空结果、超时等其它导出症状。

- H1：存储里没有 status=0。预测：原数据检查找不到 0；换成明确含 0 的固定数据且过滤逻辑正确时，应返回一行。
- H2：0 被当作未传。预测：相同数据下，status=1 正确过滤，status=0 返回全部。
- 实验：在现有测试入口传两行固定数据（status 为 0 和 1），分别调用 None、0、1。排除数据库、网络和编码变量。
- 静态预期：None 返回两行；1 返回一行；0 错误返回两行，支持 H2。只有实际执行并记录输出后才称“已复现”。
- 已授权修复时：用 `status is not None` 区分未传和 0，保留三个输入的回归断言；还要确认真实入口的解析是否将 0 变成字符串或丢弃参数。

根因结论必须说明适用范围：该函数存在过滤条件缺陷，不自动证明用户所有导出故障均由此造成。若真实请求未到此函数，需继续核查调用路径。

## 偶发与并发

- 固定版本、数据量、并发、随机种子（若有）、超时与机器条件，记录失败次数/试验次数及失败签名。
- 先找可控制的时序、屏障或模拟时钟，使竞争条件可重复；不得为了确定性改变待验证的业务语义。
- 修复前后尽量使用相同条件。0/N 次失败只表示本次未观察到，不证明概率为零；条件改变后的成功不能直接归因于代码修复。
- 环境波动、资源泄漏和真实业务竞态可产生相似症状；补能区分它们的观测，不“重跑到绿”丢弃失败。

## 无法复现与停止

可以基于完整可达代码路径静态定位确定性错误，但应标注“静态证据、未运行时复现”。仅有相关日志、最近提交或症状消失时，根因仍是假设。

停止并交付：已确认事实、剩余假设、已做实验与结果、缺失条件、最小下一步和修复授权状态。缺凭据/目标环境时明确阻塞，不靠生产写入补证据；不无限尝试信息增益很低的实验。
